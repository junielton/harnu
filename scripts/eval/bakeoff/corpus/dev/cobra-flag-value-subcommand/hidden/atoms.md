| id   | requirement                                                                                                                                                                                                                                          |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-1  | A space-delimited flag value equal to a subcommand's name stays the value of that flag instead of being taken out as the subcommand.                                                                                                                 |
| R-2  | When the first of several flags has such a value, the subcommand still runs and every flag gets its given value.                                                                                                                                     |
| R-3  | The invocations reported as working keep working: a single flag (`-z two two`), equals-delimited flags (`-z=two -o=one two`), a colliding value that is not on the first flag (`-z one -o two two`), and the subcommand first (`two -z two -o one`). |
| O-1  | The reproducing case is `-z two -o one two`, which runs `two` with zero `two`, one `one` and no positional args; `-z one -o one two` runs `two` with zero `one`, one `one` and no positional args.                                                   |
| O-2  | The fix covers short, long and mixed flags, any number of flags before the subcommand, and several values equal to the subcommand name.                                                                                                              |
| O-3  | Only the token naming the subcommand is removed; `Command.Find` returns all other args, flag values included, in their original order.                                                                                                               |
| O-4  | A boolean flag or a flag with `NoOptDefVal` does not consume the next token.                                                                                                                                                                         |
| O-5  | The first token that is not a flag value is the subcommand; later tokens with the same name stay positional args.                                                                                                                                    |
| O-6  | No subcommand is looked for after `--`, and args after `--` stay positional.                                                                                                                                                                         |
| O-7  | The fix applies at every level of nested subcommands, for values equal to a parent's or a child's name.                                                                                                                                              |
| O-8  | The fix also holds for aliases and for prefix matching, and `CalledAs` reports the alias typed.                                                                                                                                                      |
| O-9  | The `help` command is covered: `-z help -o one help two` shows help for `two`.                                                                                                                                                                       |
| O-10 | Shell completion resolves the command the same way, with the flag value kept and no spurious positional args.                                                                                                                                        |
| O-11 | Flag values alone never select a subcommand, and unrelated positional args at the root are unaffected.                                                                                                                                               |
| O-12 | `TraverseChildren` behavior stays correct.                                                                                                                                                                                                           |
