| R-1 | A `KeyboardInterrupt` that arrives while Click is handling an abort from `click.prompt()` in `Command.main()` does not escape as an unhandled exception or traceback.                                                                          |
| R-2 | The handling does not depend on timing or architecture: the race is closed rather than made less likely.                                                                                                                                       |
| O-1 | When the race hits, the run still ends through `SystemExit` as a failed run with exit status 1, with no special status such as 130.                                                                                                            |
| O-2 | Printing "Aborted!" is best effort when the race hits: it may be missing or partial, and the print is not retried or waited on.                                                                                                                |
| O-3 | The covered moments include the terminal check, the write and the flush of the abort message on stderr.                                                                                                                                        |
| O-4 | Every standalone abort is covered: visible and hidden prompts, `confirm()`, `prompt=True` options, subcommand prompts, Ctrl-D at a prompt, `ctx.abort()`, a raised `click.Abort`, and `KeyboardInterrupt` or `EOFError` from the command body. |
| O-5 | An interrupt while printing the blank line before the abort message does not escape either.                                                                                                                                                    |
| O-6 | With `standalone_mode=False`, `click.Abort` still propagates without an "Aborted!" message, and a `KeyboardInterrupt` or `EOFError` from the command still becomes `click.Abort` with the original as its cause.                               |
| O-7 | An abort with no second interrupt is unchanged: "Aborted!" on stderr and exit status 1.                                                                                                                                                        |
| O-8 | The fix is in the abort handling of `Command.main()` and adds no parameters or public API.                                                                                                                                                     |
| O-9 | `CHANGES.md` gets an entry under the unreleased version.                                                                                                                                                                                       |
