# Mission dropdown: everything about a mission in one dropdown from the Topbar pill, and the Mission pane removed

## Problem

Missions v4 put a mission in a **Mission pane** in the helper stack, opened by the Topbar pill. After a few days of daily use the operator's verdict is that the pane is too much: it takes a pane of the helper stack that other panes need, it draws things nobody acts on, and it hides the main body behind a disclosure.

Measured on the code at `main`:

| What                           | Today                                                                                                                                                                                                                  |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Size of the pane               | 7 Vue files (`MissionPane.vue` 939 lines, plus Next, Tree, Step, Sessions, Attach, Ask: 1,661 lines more) and `MissionHandoffDialog.vue`; 12 test files named `mission-pane-*` (5,507 lines)                           |
| Chrome around the content      | A 24px pane header, a "Mission" title, a state tag, a 24px progress bar with its count inside, a "Steps and timeline" disclosure that starts collapsed and keeps its state in `localStorage`, a vertical timeline line |
| What the operator opens it for | The title, the next step and the tree. Each sits behind chrome or a click                                                                                                                                              |
| A finished mission             | The Sessions section lists 61 rows, each "Works on the mission · Since Nov 14" with the same green dot (card T764)                                                                                                     |
| Step links                     | Worktree and evidence links render as boxes holding an absolute path that can be neither clicked nor selected (card BUG-288)                                                                                           |
| State dots                     | 12px glyphs whose meaning is only in `aria-label`: hovering shows nothing (card BUG-285)                                                                                                                               |
| Ask on a milestone             | The button is pressed against the step count and the summary line (card BUG-287)                                                                                                                                       |
| Next-step button               | Always under the text, in the large size                                                                                                                                                                               |

The operator's decisions of 2026-11-17, one atom per sentence, including the later scope update and the answers to the three open decisions:

- R-1 Everything about a mission goes back into a **dropdown** that opens from the Mission pill in the Topbar. The Mission pane is removed, with no "open in pane" option.
- R-2 Minimalism first: every element must be useful. For each one ask what the operator does with it; if nothing, remove it or fold it behind one line. What the operator owes is never hidden.
- R-3 The user does not see sessions. Only the view goes; the data and the backend stay (`record.sessions`, attach, the leader, the hand-off code). The card T764 (a reduced Sessions row) is closed by this, not built.
- R-4 Step links: the PR link is kept. A worktree link shows a branch name and selects that folder on click. The evidence folder becomes one "Evidence" link that opens its README. No absolute home path is drawn. Copying the path is available. A link that opens nothing is not drawn (card BUG-288).
- R-5 Every state glyph has a hover label, in en and pt-BR (card BUG-285).
- R-6 The Ask button has the spacing of a row action and never touches the count or the summary line (card BUG-287).
- R-7 The next-step button sits to the right of the text when the dropdown is wide enough and falls back under the text when it is narrow, in the compact size.
- R-8 The "Ready to close" badge above the next step repeats what the next step already says: it is removed.
- R-9 Only the current milestone is open in the tree; the others are one line.
- R-10 Behaviour that stays: one mission everywhere (chip, pill, dropdown agree), the waiting list and every owed item, Approve and Decline of a staged Done when, the close dialog, attach and attach requests, Ask on a milestone, the chooser when a session leads several missions, en and pt-BR, light and dark.
- R-11 `design.md` is the contract: the dropdown's anchoring, size, scroll, keyboard, focus and small-window behaviour are written there before any code.
- R-12 Sample data in every mockup, capture and test is neutral (the shapes of `lib/mission-sample.ts`): no real session, folder or client names.
- R-13 When the session is in no mission the pill is a quiet, icon-only pill, so the attach picker keeps a door (D-1).
- R-14 An open milestone shows at most three running steps; the rest are folded behind "{n} more steps" (D-2).
- R-15 The sample mission stays reachable as a "See a sample mission" link under the empty state's picker (D-3).
- R-16 The dropdown reserves one entry point for guided walks: a "Test it" control on a step, on a milestone and on the whole mission. It is drawn and specified now and wired to a stub that the guided-walk work replaces.
- R-17 Removing the pane also removes its helper-stack type and its persistence, and a layout saved by an older build that holds a Mission pane still loads, without the pane and without an error.

## Goals

- G-1 The operator opens one dropdown from the Topbar and, in the first screenful, reads the mission's title, how far it is, the one thing they owe next and the current milestone's steps.
- G-2 No helper-stack pane is spent on a mission, so the stack is free for panes that last minutes, such as a guided walk.
- G-3 Every element of the dropdown is something the operator acts on or needs to read; anything else is gone or one click away.
- G-4 Every state glyph says what it means, every link opens something, and no absolute path is shown.
- G-5 `design.md` describes the dropdown completely before the first line of it is built, with no new token.
- G-6 A saved layout from any earlier build opens in the new build.

**Non-goals:**

- NG-1 No change to the server's view of a mission (`mission:v4View` and its reply shape): the dropdown draws it exactly as the pane did, with the same store and the 20-second poll and no state computed in the renderer. One read-only helper may be added beside it for a link's target (AC-14) (R-10).
- NG-2 No deletion of the hand-off, session-history, attach or leader backend. `src/main/missions/sessions.ts`, `src/main/missions/handoff.ts`, the attach doors and their tests stay, with no caller in the renderer (R-3, D-4).
- NG-3 No change to what Ask, Approve, Decline, Mark done, Allow, Deny, Attach or Close do. Only where they are drawn changes (R-10).
- NG-4 No new MCP verb and no change to a verb's ACK (R-1).
- NG-5 No renaming of `src/renderer/src/lib/mission-pane-view.ts` or of the `missionPane.*` i18n namespace in this work. The names are internal; a rename is a separate, mechanical change (R-1).
- NG-6 The guided walk itself (its pane, its data, its saved runs) is not built here. Only its entry control and the seam are (R-16).
- NG-7 No dropdown for anything but a mission. The Activity bell and the other popovers are untouched (R-1).

**Anti-goals:** a dropdown that is a smaller pane (a second place to scroll, a disclosure, a state tag); a removal that leaves a layout saved by an older build blank or throwing; an element that is drawn "because the pane had it".

## Slices

Eight slices, one branch and one PR each, in one line: S-1 to S-8, each stacked on the one before. They are sequential on purpose: S-2 to S-6 all edit `MissionDropdown.vue` and the two locale files, and S-4 and S-6 both edit the tree and step components. New strings go under the `missionDropdown.*` namespace in both locale files, one block per slice, so a rebase never has to merge a block.

S-1 to S-6 build the dropdown's components beside the pane without changing what the user sees (the pill keeps opening the pane); S-7 turns the pill over to the dropdown; S-8 deletes the pane. The mockup is committed at `docs/design/mission-dropdown/`: screen `mission-dropdown` (14 states) and screen `entry` (4 states), with a capture of each state at 1280 and 360 wide, dark, EN, in its `shots/` folder.

**Gates on S-1 to S-6.** These slices change `src/` and add top-level components, but nothing in them is reachable by a user, so a CHANGELOG entry would describe something that does not exist yet. Each of their PRs carries the `no-changelog` and `no-user-docs` labels (the escape hatches the two gates already have), and S-7 carries the entry and the user guide. Each slice that adds a `Mission*.vue` file also adds its row to the design-entity map in `CLAUDE.md` and its name to the file list in `tests/mission-old-surfaces-removed.test.ts`, and each such component carries `.scrollable` on every `overflow-y-auto` element (`tests/mission-scrollbar.test.ts` reads every `Mission*.vue`).

### The Test it seam

The guided-walk work (a separate spec) owns what a walk is. This spec owns only where it starts from the dropdown, and the one place it plugs in:

- **Controls.** "Test it" on an open step's Criteria row, "Test it" on the open milestone's summary line (next to "Ask") and "Test the whole mission" in the footer at the end of a mission. They are drawn in the mockup screen `entry` (states `step-open`, `milestone`, `mission`, `closed`).
- **Seam.** `walk-entry.ts` exports `WalkSource`, `walkEntryAvailable(source)`, `startWalk(source)` and `setWalkEntryProvider(provider)` (AC-19). The two functions delegate to the installed provider; the shipped provider answers false, so S-6 ships with the controls invisible in the product and a test that installs a provider that answers true. The walk milestone installs the real provider and decides there, per source, when a walk is offered (D-6); the dropdown draws a control wherever the provider says yes.
- **The walk opens in the helper stack**, never inside the dropdown: a walk lasts minutes while the operator clicks around the app, which is why the pane left the stack in the first place (G-2). A click calls `startWalk(source)` and the dropdown closes itself; the provider opens the walk's pane.

```markdown
### Mission dropdown (Missions v4 — replaces the Mission pane)

**The Mission pane is gone** (no helper-stack pane, no "open in pane", the `mission` pane type is no

nothing, remove it or fold it behind one line. **What the operator owes is never hidden.** The dropdown
computes no state; it draws the server's view exactly as the pane did (`mission:v4View`, the same store
and 20 s poll, the same doors).

#### Anchoring, size, scroll

- **Anchor.** The pill is the anchor (`aria-haspopup="dialog"`, `aria-expanded`). The dropdown sits **6px

  pinned under it and nothing else is; every `overflow-y-auto` element carries `.scrollable`. Under **420px** of window height the footer stops being pinned and
  scrolls with the body. The body is a size container (`@container`).
- **Close.** Esc, a click outside, the pill again, or a door that ends the mission. Outside clicks
  that land on a dialog do not close it.

- **Open:** click, Enter or Space on the pill, or the `view.missionProgress` chord (it toggles the same

  Done when or a request to join); when nothing is owed, the dropdown itself (`tabindex="-1"`).
- **Focus trap:** Tab and Shift+Tab cycle inside the dropdown (a `role="dialog"`, not modal: the page

- **Dialogs** (close) are teleported after the dropdown, so at the same `--z-dialog` layer they sit above it; the dropdown becomes `inert` and dimmed; Esc closes the

   carries **Ask** at its right end (`gap: 4px 14px`, it wraps to its own line, never touching the count);
   inside an open milestone the owed steps come first, then **at most three** running steps, the rest behind
   "{n} more steps"; a step row has no Blocked chip (the flag glyph is it) and keeps the Yours chip and
   the PR link.
4. **An open step.** Blocker (with Done, continue when it is the operator's), **Criteria** (verified

   **worktree** as its branch name (click selects that folder in the sidebar) with a copy button for the
   path; the evidence as one **Evidence** link that opens its README; an address on this machine. A link
   that opens nothing is not drawn; no absolute path is ever drawn; an empty Links block is not drawn.
5. **Footer** (pinned, `border-t`, `padding: 7px 14px`): **Close mission…** (ghost, compact, `flag`).
   Not drawn when the next step already is "Close mission…", nor in the empty and chooser views.

**Dots and glyphs.** Every state glyph has a label on hover and focus (a teleported tooltip: `11px`,
`bg-surface-2`, `border-border-2`, `shadow-pop`, above the glyph or below it when there is no room) and an
`aria-label`: milestone — Not started / In progress / Done; step — To do / Running / Waiting for review /
Done / Blocked; criterion — Not settled yet / Settled. The pt-BR words are the app's translation of these,
added to `pt-BR.json` in the same change as the English ones.

**Topbar pill** (`MissionPill.vue`, S-7). Same anatomy, label and tones as the pane's pill ("{done}/{total} · {n} for you",
warning / accent / success), plus a trailing **caret** (`chevron-down`, 10px). It is a button with
`aria-haspopup="dialog"` and `aria-expanded` (not `aria-pressed`), drawn with the tone's `ring-2` while the
dropdown is open; the `view.missionProgress` chord toggles the same dropdown and is enabled whenever the pill
is drawn. A session in **no mission** draws a **muted, icon-only** pill (`border-border-2`, `text-text-3`,
`target` glyph, `title` and `aria-label` "No mission") that opens the empty state.

**Test it (the entry for guided walks).** A compact button (`h-5`, `px-2`, `11px`, the `list-checks`
glyph at 10px, label "Test it"; `aria-label` "Test it · {what it walks}") on three places: the Criteria
row of an open step (right end of the heading line), the open milestone's summary line (next to Ask) and,
when the mission is ready to close, "Test the whole mission" in the footer. It starts a walk in the helper
stack, never inside the dropdown, and is drawn only when a walk can start from that source (`walkEntryAvailable(source)`);
until then it is not drawn at all. In the footer, "Test the whole mission" shares the footer with "Close mission…" or stands alone when the next card already is that. Mockup screen `entry`.

**Empty state** (session with no mission): the pill is a muted **icon-only** pill (`border-border-2`,
`text-text-3`, title "No mission"). The dropdown shows `target` (14px, `text-text-4`), "This session has
no mission.", the picker of the open missions in this folder (Attach, with its in-place confirmation),
"Start a new mission" and, under the picker, "See a sample mission" (the sample keeps its "made up" label, its state chooser and a way to leave it), as in the pane.

**Small windows.** The body is a container, so every width rule is on the dropdown's own width, not the
window's: below **380px** the next-step button and each "more waiting" button go under their text, and the
criteria's who-settles cell goes under the criterion. Titles and step names wrap (`overflow-wrap:
anywhere`); the pill keeps its count while the breadcrumb truncates first; nothing scrolls sideways; no
control is hidden to make room.

**Not carried over:** the pane chrome, the helper-stack type and its persistence, the "Steps and timeline"
and Sessions disclosures and their `localStorage` keys (`om2tab.missionPane.sections`), the timeline line,
the Sessions row, the hand-off door, offer and dialog (view only; the backend stays), the state tag, the
Blocked chip, "Review it", the empty "no links" sentence.

**Don'ts.** ❌ Draw something the operator does nothing with. ❌ Hide an owed item behind a fold with no
count. ❌ Put a state tag or a "Ready to close" badge above the next step. ❌ Draw a second card for what the
next step already says. ❌ Open more than the current milestone by itself. ❌ Show sessions to the user.
❌ Print an absolute path or a link that opens nothing. ❌ Use the large button inside the dropdown.
```
