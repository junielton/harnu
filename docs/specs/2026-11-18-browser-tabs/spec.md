# Tabs, a start page and a load error in the browser pane

## Problem

Terms: an **operator pane** or **agent pane** is a pane whose `openedBy` is `operator` or `agent`; a **partition** is a pane's cookie store; **discarded** is a page whose view was destroyed to save memory and reloads its address when shown; a **user activation** is a real click or key press. The T564 browser spec is `docs/specs/2026-10-21-T564-browser-pane.md`.

The operator's requests of 2026-11-18, one atom per sentence:

- R-1 Have tabs in Harnu's browser pane.
- R-2 A login made in one tab is there in the pane's other tabs.
- R-3 A start page shows when a pane or tab has no address set.
- R-4 A page that fails to load shows something instead of a blank view.
- R-5 The address field shows one border on focus, not two.
- R-6 The new tab strip draws no blue accent line on the active tab.
- R-7 The agent connection is one pulsing icon; its text shows on hover.
- R-8 Every element of the pane header sits on one centre line.
- R-9 Opening the browser from the Topbar opens a tab, not one more pane.
- R-10 The tab strip, its menu and its overflow look as in the approved mockup.

## Goals

- G-1 A pane holds up to 8 tabs of one partition; with one tab it looks as it does today plus a `+` button (R-1, R-10).
- G-2 Nothing about cookies changes: every tab, including a popup tab, uses its pane's partition (R-2).
- G-3 An operator tab with no address shows a start page of servers running in the folder and recent sites; agent panes never show it (R-3).
- G-4 A tab whose main-frame load failed shows Harnu's error page with Reload and, on a `local` origin, Reload when it is up (R-4).
- G-5 The header shows one focus border, no accent line on the active tab, a compact agent icon, and one centre line (R-5 to R-8).

**Non-goals:**

- NG-1 No tab moves between panes by drag; "Move to a new pane" in the tab menu is the only move (R-1).
- NG-2 No tab groups, pinned tabs, history page UI, bookmarks or search engine; the start page's Recent list is the only kept history (R-1).
- NG-3 No change to the two partitions; an agent never opens a tab in an operator pane (R-2).
- NG-4 OAuth flows that need `window.opener` stay unsupported, as in the T564 spec's Q10 (R-1).
- NG-5 A live panel (a `page` pane) keeps one tab: no `+`, no strip (R-1).
- NG-6 On Windows the start page lists Docker servers only; terminal port detection is Linux and macOS (R-3).

**Anti-goals:** a second row of chrome for a one-tab pane; a start page that grows into a dashboard; an agent tab that lands in the operator's logged-in partition.

### Decisions taken (2026-11-18)

The Open decisions table below is the canonical record of the six choices. The detail under each is part of this spec and is approved with it:

- **D-1** The Topbar Browser button adds a tab (start page) right of the active tab of the folder's last-used operator pane and focuses its address field. Last-used = the operator pane of that folder with the latest `lastFocusedAt` (see "Last-used pane"). No operator pane in the folder, or 8 tabs in it: it opens a pane, as today. Shift+click always opens a pane. An agent pane is never a target.
- **D-2** A page's new window opens as a tab right of its opener, in the same pane and partition; A popup tab becomes the active tab; Ctrl+click (Cmd+click on macOS) on a link opens a background tab. The one-per-activation limit stays. At 8 tabs the window is refused: main sets the pane's notice (the existing notice field of the pane state) to `browserPane.notice.tabLimit`, and the notice strip (`design.md` §6 "Browser pane") says "Tab limit reached (8). Close a tab to open more." A popup tab belongs to its pane, so in an agent pane it is driven by agents under the same origin tiers as any agent tab (an `external` page still needs a lease). This replaces the T564 rule that a popup becomes an operator-class pane.
- **D-3** Agents get tabs in agent panes: `browser_open({ paneId, url })` opens a tab in an agent pane of the same folder; an operator or page pane is `NOT_AN_AGENT_PANE`. Every tab verb takes an optional `tabId` (default: the active tab); `browser_list` lists tabs. The 4-agent-pane cap stays; a pane holds at most 8 tabs (`TAB_LIMIT`).
- **D-4** The compact pulsing agent icon replaces the text pill in the browser and the terminal pane headers; Paused and Disconnected keep their text pill.
- **D-5** "Running in this folder" lists host ports of the folder's Docker stacks and ports listened on by processes running in the folder's Harnu terminals.
- **D-6** After a restart every tab returns in order with its address and title; only the persisted active tab loads, the others stay discarded; a start-page tab returns as a start page; an `error` tab reloads its address. A hidden tab is discarded after 10 minutes.

### Behaviour

The approved mockup has one screen, `browser-pane`, in ten states: `single`, `start`, `new-tab`, `load-error`, `tabs`, `tab-menu`, `overflow`, `overflow-list`, `agent`, `agent-hover`. Each has a capture AC below. The terminal pane reuses the same agent icon component and has no screen of its own.

**Tab contract.** A `tabId` is `tab-<8 hex>`, minted by main, persisted with the pane, stable across a restore and a move. The per-tab record main sends the renderer (`src/shared/browser-tabs.ts`) is `{ tabId, url, title, favicon, loading, hostView, loadError?, waitingForUp, discarded, active, agentActive }`, where `loadError` is `{ code, url, host, port, local }` while `hostView` is `error`; a pane's state carries `tabs` in order and `activeTabId`. The IPC S-2 adds (`ipcMain.handle`, exposed on `window.api`): `browser:tab:new` → `browserTabNew(paneId, { url?, hostView?, afterTabId?, background? }) → { tabId }`; `browser:tab:close` → `browserTabClose(paneId, tabId)`; `browser:tab:activate` → `browserTabActivate(paneId, tabId)`; `browser:tab:duplicate` → `browserTabDuplicate(paneId, tabId) → { tabId }`; `browser:tab:move-to-pane` → `browserTabMoveToPane(paneId, tabId) → { paneId }`; `browser:tab:reload` → `browserTabReload(paneId, tabId)`. Refusals come back as `{ ok: false, error }` with `TAB_LIMIT`, `TAB_NOT_FOUND` or `PANE_LIMIT`. S-2 mints a `tabId` for the single tab of a `page` pane too. Until S-3 and S-4 land, `stores/browser.ts` keeps the pane-level `url` and `title` the renderer reads today, derived from the active tab. There is no reorder (NG-1). The persisted browser pane entry in `helpers.json` gains `tabs: [{ tabId, url, title, hostView }]`, `activeTabId` and `lastFocusedAt`; an entry without `tabs` restores as one tab from its `url`. Creating a tab takes `hostView?: 'page' | 'start'` (default `page`), and the pane's persisted state keeps each tab's `hostView`; S-2 owns both, S-3 reacts to them, S-4's callers pass `start`.

**The host seam (S-2).** Every `BrowserReadHost` method and every host call keyed by `paneId` keeps its signature and acts on the pane's active tab. S-2 adds an optional `tabId` parameter to those methods and to the `drive` call that sets a tab's activity word, resolving `(paneId, tabId?)` to the tab's view entry; S-6 only passes `tabId` through. A `ViewEntry` becomes per tab: view, debugger readers (console ring, snapshot refs) and activity word.

**Tabs (main).** A pane owns an ordered list of tabs and its active tab. Each tab owns one `WebContentsView` in the pane's partition (ADR-0026). Only the active tab's view is attached and bounded. Pane-level state: partition, `openedBy`, owner, Disconnect, pause, emulation, zoom and network capture. Tab-level state: page, history, readers, activity word, discard state, and the lease, which stays per view and origin as today (a lease on one tab does not cover another). Closing the last tab closes the pane, for operator and agent panes alike; a later verb on it is `PANE_NOT_FOUND`. Registry bookkeeping: verbs in flight are counted per tab (they block that tab's discard); the write and input bookkeeping behind `othersWrote`, `operatorInteracted` and the emit gate's agent-input window stays per pane, so a verb on any tab counts for its pane. Emulation and zoom are applied to a tab's view when it is created and when it revives.

**Discard per tab.** A tab is hidden when it is not the active tab of a shown pane; its hidden clock starts when it stops being shown. After 10 minutes the sweep destroys its view and marks it discarded; activation revives it. What blocks a pane's discard today (a download or verb in flight, network capture) blocks each tab's discard the same way: a download or verb blocks its own tab, capture blocks every tab of its pane.

**Network capture.** Capture belongs to the pane: `start` attaches it to every live tab's view, a tab created or revived while it runs joins it, a discarded tab's entries stay in the buffer, a moved tab's earlier entries stay with the old pane. One expiry and one `stop` cover the pane. Each entry carries its `tabId`.

**Move to a new pane.** Main creates a pane record with a new `paneId` that copies partition, `openedBy`, `ownerSessionId`, Disconnect, emulation and zoom; the tab keeps its `tabId`, page and history (its view is detached from the old pane and attached to the new one). Pause and capture are not carried. A lease is keyed by pane and view token, so the move re-keys the tab's active lease to the new `paneId` with the same view token; it stays active. The renderer places the new pane below the current one through the same `browser:popup` event a popup pane uses today. An agent pane at the 4-pane cap is refused `PANE_LIMIT`; a disconnected pane does not count toward the cap, as today. Disabled on a pane's only tab.

**The host placeholder.** Per tab, main owns `hostView`: `page` (the view shows), `start` or `error`. When the active tab's `hostView` is `start` or `error`, main hides its view and the renderer draws the matching component in the pane's host div, as it draws the discarded placeholder today. Until S-5 lands, `start` draws an empty `--bg` host with the address field focused; S-5 replaces it with the start page. The new-tab state of the mockup shows the start page, so its capture belongs to S-5. `start` is set only when a tab is created with `hostView: 'start'` (by `+`, the Topbar button and "New tab to the right", all in S-4) or restored with it (S-2); a popup tab stays `page` while it loads `about:blank`. `error` is set by a main-frame `did-fail-load` with any code but `ERR_ABORTED`; subframe failures never set it. A main-frame commit sets `page`. Agent panes never show the start page. On an `error` tab the read verbs return `ok` with `loadError: { code, url }` and an empty page; `screenshot` returns `loadError` and no image, since the view is hidden.

**Load error.** `unplug` 22px `--text-3`, a title and one hint line from this table (keys under `browserPane.loadError.*` in `en.json` and `pt-BR.json`), the error code in mono `--text-4`, then **Reload** (primary) and, on a `local` origin only, **Reload when it is up**: a TCP connect to the host and port (default 80 for `http`, 443 for `https`) every 2 s, reloading on the first success, started and cancelled through `browser:tab:reload-when-up` → `browserTabReloadWhenUp(paneId, tabId, on: boolean)`, with the tab's `waitingForUp` reporting the state; it stops on success, after 10 min, on any navigation of the tab and when the tab closes, and keeps polling while the tab is hidden. While it polls the button reads "Waiting for ‹host:port›…" and a second click cancels it.

| codes                                            | title                                  | hint                                                             |
| ------------------------------------------------ | -------------------------------------- | ---------------------------------------------------------------- |
| `ERR_CONNECTION_REFUSED` on a `local` origin     | ‹host› refused to connect              | Nothing is answering on port ‹n›. Start the server, then reload. |
| `ERR_CONNECTION_REFUSED`, `ERR_CONNECTION_RESET` | ‹host› refused to connect              | The site may be down. Try again in a moment.                     |
| `ERR_NAME_NOT_RESOLVED`                          | ‹host›'s address could not be found    | Check the address for a typo.                                    |
| `ERR_CONNECTION_TIMED_OUT`, `ERR_TIMED_OUT`      | ‹host› took too long to respond        | The site may be slow or unreachable from this network.           |
| `ERR_INTERNET_DISCONNECTED`                      | No internet connection                 | Check your connection, then reload.                              |
| `ERR_CERT_*`                                     | The connection to ‹host› is not secure | Its certificate was not accepted, so the page was not loaded.    |
| any other code                                   | ‹host› could not be loaded             | The page failed to load.                                         |

**Start page.** "Running in this folder" and "Recent", each left out when empty; the address field is focused and empty.

- _Docker rows_ come from the folder's stacks in the containers scan (stack attribution and each running container's `ports`, `src/main/containers/containers-core.ts`): name = the compose service or container name, source label `docker`.
- _Terminal rows_ come from the folder's live Harnu terminals through a read-only accessor S-5 adds to `src/main/terminal-registry.ts`: `listTerminalsByFolder(folder) → [{ terminalId, shellPid }]`. Linux: the shell's descendant pids from `/proc/<pid>/task/*/children`, their socket inodes from `/proc/<pid>/fd`, matched to `LISTEN` rows of `/proc/net/tcp` and `/proc/net/tcp6`. macOS: `lsof -nP -iTCP -sTCP:LISTEN -a -p <pids>`. Name = the folder's basename; source label = the listening process's name. Loopback and wildcard binds show as `localhost:<port>`; a listener bound only to another address shows as `<address>:<port>`.
- The seam: `local-servers.ts` is pure and takes `stacks: [{ folder, name, hostPorts }]`, `terminals: [{ folder, shellPid }]` and `listeners(pids) → [{ pid, port, processName }]`; `local-servers-shell.ts` supplies `listeners` (the `/proc` reader, or `lsof`); `browser-service.ts` wires the containers scan and the terminal registry into it.
- Rows are deduped by port (Docker wins), sorted by port, refreshed each time a start page shows and at most every 5 s while it stays shown. A row opens in the same tab through the address bar's existing navigation call. The renderer reads both lists through `browser:start:servers` → `browserStartServers(folder) → [{ name, url, source }]` and `browser:start:recent` → `browserStartRecent(folder) → [{ title, url, host }]`. On Windows (`process.platform === 'win32'`) the terminal rows are empty.
- _Recent_ is recorded by S-5 through a hook on the main-frame `did-navigate` of each operator tab (popup tabs included; in-page `pushState` navigations are not recorded) with a 2xx–3xx status. It is a per-folder list in the app's user data (`browser-recent.json`): origin + path (query and fragment dropped) + title, newest first, deduped by origin + path, at most 50 stored and 8 shown. To keep secrets out of it, a path segment that looks like a token (20 or more characters of letters, digits, `-` or `_`) is replaced by `…`, and a navigation whose path contains (case-insensitively) `reset`, `token`, `oauth`, `callback`, `verify` or `magic` is not recorded. Agent panes, `about:blank`, error pages and `harnu-page:` pages are never recorded. Clearing Recent is not part of this spec: it joins Clear browsing data when that pane-menu action lands (`design.md` §6 "Browser pane" defers it).

**Tab strip.** One tab: today's header (globe, title, comment, ⋯, maximize, close) plus `+` before the comment button. Two or more: the strip replaces globe and title in the same header. A tab shows a favicon 12px (the page's, else the host's first letter in the origin badge's colours: `local` `--green-soft` and `--green`, `external` `--surface-2` and `--text-2`, `page` `--accent-soft` and `--accent`), its title 11px truncated, and a 14px close `x` on hover and on the active tab. Inactive: `--text-3`, hover `--surface-2`. Active: `--bg` and `--text`, covering the header's 1px bottom border with a 1px `--bg` shadow so it opens into the address bar; **no accent line**. `+` follows the last tab, adds a tab right of the active one and focuses its address; at `TAB_LIMIT` it is disabled with the hint "Tab limit reached (8)".

**Overflow.** The pure layout (`src/renderer/src/lib/browser-tabs-view.ts`) takes the strip width W (header width minus the right-hand buttons and `+`) and the n tabs, and returns the first mode that fits:

| mode   | active tab         | inactive tabs      | fits when                           |
| ------ | ------------------ | ------------------ | ----------------------------------- |
| full   | 168px              | 168px              | n × 168 ≤ W                         |
| short  | 168px              | 112px, title kept  | W > 480 and 168 + (n − 1) × 112 ≤ W |
| shrink | equal width ≥ 80px | equal width ≥ 80px | n × 80 ≤ W                          |
| icons  | 168px              | 28px icon          | 168 + (n − 1) × 28 ≤ W              |

When none fits, the icons mode applies with 36px reserved for a `+N` button (mono 10.5px, before `+`): the strip keeps the active tab and the first k = max(0, ⌊(W − 36 − 168) ÷ 28⌋) inactive tabs in order, and the rest move behind `+N`; the active tab is never moved. `+N` opens a standard context menu listing every tab in order with the active one marked; picking one activates it. Samples: W 600, n 3 → full; W 700, n 5 → short; W 600, n 5 → shrink (120px each); W 300, n 5 → icons; W 250, n 9 → icons with k = 1 and 7 tabs behind `+N`.

**Tab menu** (right-click a tab): **New tab to the right**; **Reload**; **Duplicate** (a new tab right of it loading the same URL, without history or scroll); **Move to a new pane** (above); **Close other tabs**; **Close tab**.

**Keys.** Linux and Windows: Ctrl+T new tab, Ctrl+W close tab; macOS: Cmd+T and Cmd+W. Everywhere: Ctrl+Tab and Ctrl+Shift+Tab next and previous. They are pane chords: caught through `before-input-event` when focus is in the page, and by the pane chrome when focus is in the header or address bar, before the page sees them. While a browser pane has focus its close-tab chord wins over the app's close-session chord (`src/renderer/src/composables/useShortcuts.ts`); elsewhere nothing changes.

**Last-used pane.** Focus in a pane's header or address bar makes the renderer call `browser:pane:focused` → `browserPaneFocused(paneId)`; a `focus` event of a tab's page `webContents` is caught in main. Either way main stamps the pane's `lastFocusedAt` and sends it in the pane state, and the renderer persists it with the pane in `helpers.json`, so the order survives a restart. S-4 wires both. A pane with no stamp ranks by creation time, newest first, below every stamped pane.

**Agent icon (browser and terminal headers).** An 18px round `--accent-soft` icon with `bot` 10px `--accent` and the `pulse-ring` halo of `design.md` §7, its `--pulse-from` set to 0.69 (18 ÷ 26); still under `prefers-reduced-motion`. Hover or keyboard focus shows a tip: "Connected to ‹session›" and what it is doing ("Driving this tab · ‹host›", "Reading", "Typing"; the words are the existing chip words). Disconnect stays an `unplug` icon button beside it. Paused and Disconnected are the existing chip states (`design.md` §6 "Browser pane", Connection chip table) and keep their pills. The tab whose activity word is live (`agentActive`, set by S-2's tab-aware `drive`) shows a 6px accent dot in place of its favicon; S-7 draws the dot in the strip.

**Focus and centre line.** The address input carries `.no-default-ring`, so its own `--accent-line` border is the only focus mark. The header is 24px with a 1px bottom border, so its content box is 23px; every child is centred on it (the strip's buttons use `align-self: center`).

**Agent verbs.** `browser_open({ folder, paneId, url })` opens a tab in that agent pane and returns `tabId`; without `paneId` it opens a pane, as today. Tab verbs, taking `tabId?`: `browser_navigate`, `browser_close` (closes that tab; without it, the pane; closing the last tab says `paneClosed: true`), `browser_snapshot`, `browser_screenshot`, `browser_console`, `browser_wait_for`, `browser_eval`, `browser_click`, `browser_type`, `browser_fill`, `browser_press`, `browser_upload`, `browser_download`. Pane verbs ignore tabs: `browser_emulate`, `browser_network`, `browser_set_data`, `browser_patch`. Reads (`snapshot`, `console`, `eval`, `wait_for`) work on a background tab without switching; `screenshot` and the input verbs first activate the tab and say `activated: true`. A discarded tab revives first and says `revived: true`. An unknown `tabId` is `TAB_NOT_FOUND`; a ninth tab is `TAB_LIMIT`; a `paneId` of another folder is `PANE_NOT_FOUND`, as today. A `page` pane has one tab, whose `tabId` the verbs accept. `browser_list` gives each pane `tabs: [{ tabId, url, title, active, state }]` with `state` `live` or `discarded`.

**Design tokens.** No new token: every colour, radius and motion value is an existing `design.md` §9 token or the `pulse-ring` keyframe. The new sizes (the overflow table, the 18px icon) are written into `design.md` §6 "Browser pane" by the slice that builds them, before its code.
