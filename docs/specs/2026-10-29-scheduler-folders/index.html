Context and decisions

Problem. Today the worker column is a flat list (Pinned / Enabled / Off). With 17–45 workers across 6 folders, the folder becomes a truncated alias in the row meta (ma… · m… · every 15m), three "PR Review Watcher" workers from different repos are indistinguishable, and nothing says whether a worker keeps failing or what it found last.

Common proposal for the 3 variants. Group by folder (header with an identity colour, initial, count, health). The pin becomes an icon on the name and sorts inside the folder; folders with something running or failing rise. (Round 1 also drew a 2px cycle bar per row; revision 2 dropped it.)

Token decision to approve. The system has no per-folder colour. The mockups use the --term-ansi-* palette (already defined in every theme) as the folder hue, and tints via color-mix(var(--fh) N%, transparent). Implementing it requires declaring this in design.md §2/§9 first. Risk: coral (bright-red) sits close to the failure red — mitigated because the state always carries a word plus a dot.

Round 1: A = minimal change (same row, same width). B = maximum information per row. C = triage focus (filters, "Up next"). They can be combined: e.g. B's header + C's filters.
