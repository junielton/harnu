# Load JSON Records Held Under a Top-Level Key - Specification

**Approved**: 2026-11-07 - user: "Yes, approved. Looks right, go ahead."

## Problem Statement

Many JSON exports wrap their records in an envelope object: `{"Version": "5.5.52.6", "List": [{...}, {...}]}`. Today `sqlite-utils` treats any top-level object as one row, so this file becomes a single row with `List` stored as JSON text, and users run the file through `jq .List` first. Two opt-in options fix this: `--key KEY` reads the records from a named top-level key, and `--auto-key` finds that key by a rule of thumb. Without either option nothing changes.

## Goals

- [ ] `sqlite-utils insert data.db t alaska.json --key List` and `--auto-key` each insert one row per object in `List`, with no `jq` step.
- [ ] Without `--key` or `--auto-key`, every command and `rows_from_file()` behave exactly as today: a top-level object is one row.

## Out of Scope

| Feature | Reason |
| ------- | ------ |
| Newline-delimited JSON as an envelope source | Each line is already one record; the request is about a single JSON document. |
| Envelopes nested deeper than the top level (`{"data": {"items": [...]}}`), and JSON paths in `--key` | Operator confirmed: top level only. |
| Automatic unwrapping with no option passed | Operator: "It must not be automatic". |
| A new rule for non-object elements inside the `--key` list | Operator: "Those elements behave exactly as they do in a top-level list today, with no new rule". |
| `Table.insert_all()` and other Python methods that take dicts, not JSON | They never parse JSON. |

## User Stories

### P1: Read records from a named key in Python ⭐ MVP

**User Story**: As a Python user, I want `rows_from_file(fp, key="List")` so that I get the records of an envelope document.

**Why P1**: Every CLI entry point is defined by this rule.

**Acceptance Criteria** (the Alaska document is the request's example: `{"Version": "5.5.52.6", "List": [{"Description": "Nonpartisan", "Id": 1, "ExternalId": ""}, {"Description": "Undeclared", "Id": 2, "ExternalId": ""}]}`):

1. WHEN `rows_from_file()` is called with `key="List"` on the Alaska document THEN the system SHALL return exactly the two objects of `List`, in file order, with `Format.JSON`.
2. WHEN `key` names a key whose value is an object THEN the system SHALL return a list holding that one object.
3. WHEN `key` names a key whose value is `[]` THEN the system SHALL return zero rows without raising.
4. IF `key` names a key the top-level object does not have THEN the system SHALL raise `RowsFromFileBadJSON` with the message `Key "Missing" not found in the top-level JSON object` (the key's name in place of `Missing`).
5. IF `key` names a key whose value is a string, number, boolean or null THEN the system SHALL raise `RowsFromFileBadJSON` with the message `Key "Version" does not hold a list or an object`.
6. IF `key` is passed and the top-level JSON value is a list THEN the system SHALL raise `RowsFromFileBadJSON` with the message `Cannot read key "List": the top-level JSON value is not an object`.
7. WHEN the list under `key` holds non-object elements THEN the system SHALL return the same rows, or raise the same error, as `rows_from_file()` does for that list as the top-level document.
8. WHEN `format=None` and the input is detected as JSON THEN the system SHALL apply `key` exactly as with `format=Format.JSON`.

**Independent Test**: `rows_from_file(BytesIO(alaska), key="List")` returns the two records.

---

### P1: Find the records key automatically in Python ⭐ MVP

**User Story**: As a Python user, I want `rows_from_file(fp, auto_key=True)` so that the one key holding a list of objects becomes the rows.

**Why P1**: The request's rule of thumb.

**Acceptance Criteria**:

1. WHEN `rows_from_file()` is called with `auto_key=True` on the Alaska document THEN the system SHALL return exactly the two objects of `List`, in file order, with `Format.JSON`.
2. The system SHALL treat a top-level key as a candidate only when its value is a non-empty list whose every element is an object, so `[]`, a list of scalars, a list mixing objects and scalars, an object and a scalar are never candidates.
3. IF `auto_key=True` and two or more keys are candidates THEN the system SHALL raise `RowsFromFileBadJSON` with the message `Multiple top-level keys hold a non-empty list of objects: "users", "groups"`, naming every candidate in document order.
4. IF `auto_key=True` and no key is a candidate THEN the system SHALL raise `RowsFromFileBadJSON` with the message `No top-level key holds a non-empty list of objects`.
5. WHEN `auto_key=True` and the top-level JSON value is a list THEN the system SHALL return the same rows as the call without `auto_key`.

**Independent Test**: `rows_from_file(BytesIO(alaska), auto_key=True)` returns the two records.

---

### P1: Argument rules in Python ⭐ MVP

**User Story**: As a Python user, I want misuse of `key=` and `auto_key=` to fail clearly so that I do not import the wrong data.

**Why P1**: The operator fixed each of these rules.

**Acceptance Criteria**:

1. IF `rows_from_file()` gets both `key` and `auto_key=True` THEN the system SHALL raise `ValueError` with the message `Cannot use key= and auto_key= together`.
2. IF `format=` is `Format.CSV`, `Format.TSV` or `Format.NL` and `key` or `auto_key=True` is passed THEN the system SHALL raise `ValueError` with the message `key= and auto_key= only apply to JSON`.
3. WHEN `format=None`, `key` or `auto_key=True` is passed and the input is detected as CSV or TSV THEN the system SHALL return the same rows and format as the call without them.

**Independent Test**: each misuse raises `ValueError` before any row is read.

### P1: `--key` and `--auto-key` on insert, upsert and bulk ⭐ MVP

**User Story**: As a CLI user, I want `sqlite-utils insert data.db records alaska.json --key List` so that the envelope file imports without `jq`.

**Why P1**: The request.

**Acceptance Criteria** (`alaska.json` holds the Alaska document):

1. WHEN a user runs `sqlite-utils insert data.db records alaska.json --key List` THEN the system SHALL create table `records` holding the two `List` objects as two rows with columns `Description`, `Id`, `ExternalId` and no `Version` or `List` column.
2. WHEN a user runs `sqlite-utils insert data.db records alaska.json --auto-key` THEN the system SHALL create table `records` holding the same two rows as criterion 1.
3. WHEN a user runs `sqlite-utils upsert data.db records alaska.json --key List --pk Id` on a table that already holds `{"Id": 1, "Description": "Old", "ExternalId": ""}` THEN the system SHALL leave two rows, with row `Id` 1 holding `Description` `Nonpartisan`.
4. WHEN a user runs `sqlite-utils bulk data.db "insert into records (Id, Description) values (:Id, :Description)" alaska.json --key List` THEN the system SHALL execute the SQL once per `List` object, leaving two rows.
5. WHEN a user runs `insert` with `--key List --flatten` on a document whose `List` objects hold a nested object `{"a": {"b": 1}}` THEN the system SHALL store column `a_b` with value `1`.
6. WHEN a user reads the document from standard input (`-`) with `--key List` THEN the system SHALL insert the same two rows as criterion 1.
7. IF `--key` names an absent key THEN the system SHALL exit with code 1 and print `Error: Key "Missing" not found in the top-level JSON object`.
8. IF `--auto-key` finds two or more candidate keys THEN the system SHALL exit with code 1 and print `Error: Multiple top-level keys hold a non-empty list of objects: "users", "groups"`.
9. IF `--key` or `--auto-key` raises a data-shape error THEN the system SHALL leave the database without the target table.
10. IF a user passes both `--key` and `--auto-key` THEN the system SHALL exit with code 1 and print `Error: Cannot use --key and --auto-key together`.
11. IF a user passes `--key` or `--auto-key` together with `--csv`, `--tsv`, `--nl`, `--lines` or `--text` THEN the system SHALL exit with code 1 and print `Error: --key and --auto-key only apply to JSON input`.

**Independent Test**: run criterion 1's command on the request's example and `select * from records` returns two rows.

---

### P1: `--key` and `--auto-key` on memory ⭐ MVP

**User Story**: As a CLI user, I want `sqlite-utils memory alaska.json "select * from alaska" --key List` so that I can query an envelope file directly.

**Why P1**: Operator: "Q4 a: all of them".

**Acceptance Criteria**:

1. WHEN a user runs `sqlite-utils memory alaska.json "select * from alaska" --key List` THEN the system SHALL output the two `List` objects as two rows.
2. WHEN a user runs `sqlite-utils memory alaska.json "select * from alaska" --auto-key` THEN the system SHALL output the same two rows.
3. WHEN a user passes two JSON files to `memory` with `--key List` THEN the system SHALL load the `List` records of each file into that file's table.
4. WHEN a user passes a CSV file and a TSV file (detected, or by `:csv` / `:tsv` suffix) to `memory` alongside a JSON file with `--key List` THEN the system SHALL load the CSV and TSV tables with the same rows as without `--key`, and exit with code 0.
5. WHEN a user passes an input with the `:nl` suffix to `memory` with `--key List` THEN the system SHALL load that table with the same rows as without `--key`, and exit with code 0.
6. IF `--auto-key` finds no candidate key in a JSON input to `memory` THEN the system SHALL exit with code 1 and print `Error: No top-level key holds a non-empty list of objects`.
7. IF a user passes both `--key` and `--auto-key` to `memory` THEN the system SHALL exit with code 1 and print `Error: Cannot use --key and --auto-key together`.

**Independent Test**: criterion 1's command prints two rows.

---

### P1: Default behaviour unchanged ⭐ MVP

**User Story**: As an existing user, I want a top-level object to keep importing as one row when I pass neither option.

**Why P1**: Operator: "a top-level object has to keep importing as one row, exactly as now".

**Acceptance Criteria**:

1. WHILE neither `key` nor `auto_key` is passed, the system SHALL return the Alaska document from `rows_from_file()` as a list holding that one object.
2. WHILE neither `--key` nor `--auto-key` is passed, the system SHALL insert the Alaska document with `sqlite-utils insert` as one row with columns `Version` and `List`.
3. WHILE neither `--key` nor `--auto-key` is passed, the system SHALL load the Alaska document with `sqlite-utils memory` as one row with columns `Version` and `List`.

**Independent Test**: the existing test suite passes unchanged, and criteria 1-3 hold on the Alaska document.

### P2: Documentation

**User Story**: As a user reading the docs, I want both options explained with the envelope example so that I find them without reading `--help`.

**Why P2**: The feature works without it, but nobody discovers it.

**Acceptance Criteria**:

1. The system SHALL document `--key` and `--auto-key` in `docs/cli.rst` under "Inserting JSON data", with the request's envelope example.
2. The system SHALL describe the `key` and `auto_key` parameters in the `rows_from_file()` docstring.
3. The system SHALL keep `docs/cli-reference.rst` in sync with the new `--help` output, so `uv run cog --check README.md docs/*.rst` exits 0.

Implicit-requirement dimensions: input validation and failure states are covered above. Remaining dimensions N/A for this scope: the change is a pure in-process parse of one local document, with no auth, concurrency, retry, expiry, external dependency, logging or state transition.
