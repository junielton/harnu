# Assumptions

The spec (`docs/specs/2026-11-07-json-top-level-key/spec.md`) left the following unsettled. Each bullet gives what I assumed, then the gap that forced it.

- **Where the new insert checks sit relative to the existing file-presence checks.** The "both options" and "JSON input only" checks run right after the CSV switch line, so they come after the existing `--code cannot be used with a FILE argument` and `Provide either a FILE argument or --code` checks. As a result, `insert db t --key a --auto-key` with no FILE and no `--code` reports the missing-FILE error. *Gap:* S-2 orders the new checks among themselves and says the JSON-input check sits right after the CSV switch line, but it never places the both-options check relative to the existing FILE checks.
- **"Output starting `Error:`" when the input is a file path.** For a file path (not stdin), the existing `file_progress()` progress bar prints its empty label to stdout as a blank line on a non-TTY. That line comes before the `Error:` line on stderr, so with Click 8.5's `CliRunner`, `result.output` starts with `\n` and `result.stderr` starts with `Error:`. I kept this existing behaviour, since NG-7 says error paths these options don't add must not change. The AC-15 tests feed the input on stdin, as the existing error tests do, and the AC-29 tests, which name `alaska.json` as a file, assert that `result.stderr` starts with `Error:`. *Gap:* AC-15, AC-21 and AC-29 say "output starting `Error:`" without saying which stream, or whether the input comes from a file or stdin.
- **Option position in `--help`.** `--key` and `--auto-key` are appended at the end of `_import_options`, after `--encoding`. In `memory` they sit right after `--flatten`. *Gap:* the spec gives the option definitions but not where they go in the decorator lists, and that order decides `docs/cli-reference.rst`.
- **"Inserts zero rows" for `--key List` on `{"List": []}` (AC-16).** `insert_all()` with no rows doesn't create the table, so the test asserts the `records` table doesn't exist. *Gap:* the spec doesn't say whether a table with zero rows should be created.
- **Error message wording.** Keys are quoted with `repr()` (e.g. `Key 'Missing' was not found in the top-level JSON object`). The two-candidate error lists the keys comma-separated, in document order. *Gap:* the spec leaves wording free and only constrains what each message must contain.
- **Both slices in one checkout.** S-1 and S-2 are built in this one working directory, one commit per slice (S-1 first), instead of two worktrees or branches. *Gap:* the slices say `substrate: worktree` and `depends-on: S-1`, but the builder task gives a single directory.
- **No changelog entry.** I didn't add an entry to `docs/changelog.rst`. *Gap:* the spec asks for docs in `docs/cli.rst`, `docs/cli-reference.rst` and `docs/python-api.rst` only, and `docs/changelog.rst` is in neither slice's `files-may-touch`.
- **Lint and cog run without `uv`/`just`.** There is no network, and `just`, `flake8`, `mypy`, `pyright`, `ty` and `codespell` aren't installed in `.venv`. So for AC-31/AC-32 I ran only `black . --check` and `cog --check README.md docs/*.rst` from `.venv/bin`. For AC-22 I regenerated with `.venv/bin/cog -r README.md docs/*.rst`, and for AC-23/AC-28 I ran pytest through `.venv/bin/python -m pytest`. The new code keeps under flake8's `max-line-length = 160` and adds no imports it doesn't use, but the type checkers weren't run. *Gap:* the proofs name `uv run ...` and `just lint`, which can't run in this environment.
