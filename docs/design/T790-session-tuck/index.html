Context and decisions

Problem. When testing a CMS with a guided walk plus a browser pane, the helper stack has no room: the divider pins the session at 40% (clamp [0.4, 0.8]) and "expand to window" only expands one pane.

Proposal. Dragging the divider past the floor arms the tuck (accent divider, dimmed session, dashed line marking the floor). Releasing while armed tucks the session away; releasing earlier springs back to 40%. A thin strip stays on the edge and brings the session back at 40%.

The strip. At rest: 14px wide, state dot + grip. On hover: widens to 20px, shows a chevron and a chip with the session name, its state and "Click or drag to bring the session back" + the shortcut. Needs you: soft amber background, blinking dot, vertical "Needs you" tag.

D-1 (decided: side by side). While tucked in the side-by-side orientation, the stack takes the full width; the mockup lays the panes out side by side (walk 36% | browser 64%) instead of stacked, which is what the use case needs.

D-2 (provisional, executor checks). The Ctrl Shift J shortcut is a placeholder; the executor checks it for conflicts in the keybindings map.

Open a screen alone and hover the strip in the tucked state: the hover is real. The mockup uses only the default dark theme.
