Context

What this is. A helper-stack pane that walks the operator through a feature, a PR or a mission, one check at a time. It is the step-by-step skill’s walk moved from chat to a panel. A walk is its own object (a source, a list of checks, a run history, saved per repo); a Mission is just one place that can start one. Two sample walks: the Mission dropdown (9 checks, source: a mission) and a CSV export (6 checks, source: PR #48 or the feature just built).

How to read it. No iframes (they render blank in Harnu’s own page panes). Every state below is a PNG capture at the width, theme and language you pick in the bar above; open alone ↗ opens the live screen with the same choices, and the live screen has its own EN / PT-BR / Dark / Light switch at the bottom right. In a live screen every data-goto works: walk it ↗ under Flows clicks through like the app. Serve the folder with python3 -m http.server inside mockup/, or open the files directly.

Look. The tokens, buttons, cards and the entry dropdown are the Mission dropdown mockup’s, so the two sit side by side. Nothing here is a new token.

Entry from a mission: Test it on a step, a milestone or the whole mission entry

The Mission dropdown (reused from the dropdown mockup) with Test it at three levels: an open step (Criteria row), a milestone (next to Ask) and the whole mission (footer, at the end). A mission is ONE source of a walk, not its home. The walk opens in the helper stack, never inside the dropdown.

The walk pane (helper stack) walk

One pane, 19 states. 560 = a wide pane, 360 = a narrow one. ?walk=mission|export and ?src=mission|milestone|all|pr|feature pick the sample walk and its source (the source line under the pane header); ?n=1..3 picks the served check; ?kind=next on working shows the prepare variant. The EN / PT-BR / Dark / Light switch at the bottom right of a frame is mockup chrome, not product.

The Walks library (helper stack) library

A list of saved walks for this repo: title, source, last run date, outcome, Re-run and Open. Not a dashboard. Empty: how a walk starts, with a copyable command.

Flows

  1. entry/step-open via “Test it”
  2. walk/roadmap via “Start with 1”
  3. walk/step via “Done”
  4. walk/step via “Done (my check finds a file)”
  5. walk/check-failed via “Follow anyway (unverified)”
  6. walk/step via “Done”
  7. walk/working

It did not work: one line and a screenshot, one correction, the same step again — walk it ↗

  1. walk/step via “Failed”
  2. walk/failed via “Send”

  4. walk/step

Explain more: why it matters and extra checks under the same step — walk it ↗

  1. walk/step via “Explain more”
  2. walk/explain-more via “Explain more (again folds it back)”
  3. walk/step

I didn’t get this step: the same step, said more simply — walk it ↗

  1. walk/step via “I didn’t get this step”
  2. walk/did-not-understand via “Done”
  3. walk/working

Zoom the expected-result image — walk it ↗
