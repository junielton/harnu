# T536 U4 — Layers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the operator restack the selected nodes (send to back, send backward, bring forward, bring to front) from the properties panel, make Save write the stacking order the board actually shows, and let the agent set the same order through `zIndex` on `draw_canvas` `add_node` / `update_node`, without a single new key landing in the file of a board nobody restacked.

**Architecture:** Stacking stays in the node's existing top-level `zIndex` field, which every released reader already parses, renders and keeps (C1). A new pure renderer module, `canvas/canvas-layers.ts`, owns four things: the order a document renders in (`documentStackOrder`: stable sort by `zIndex`, a missing one counting as `1`, which is what X6 gives every unstacked node on a fresh `fromJSON`, so it is also the order every older build shows), the z each node is **rendered** with (`renderStackZ`: distinct values, never written to the file), the four moves (`reorderStack`), and the Save rule (`savedZIndexes`): when the live order equals the order the document would render in, Save writes nothing new; when it differs, every node gets its rank `1..n`. Rendering with distinct z is load-bearing: X6 breaks a z tie by its current collection order, so if unstacked nodes loaded tied at 1, undoing a restack would restore the z values but not the order. Edges stay at `zIndex: 0` and are never restacked, so no move can put a node under the arrows. A reorder writes ranks to the live cells in one History batch (one undo step). A theme redraw renders from the live z values verbatim, so undo after a theme switch restores the exact previous order. The same task family closes a Save path that drops an arrow's document fields: an edge's `label`, `router` and `props` now ride in its cell `data`, so an arrow deleted, saved and brought back by undo is written whole (this is what makes U5's reader-first premise true; see Open point 7).

**Tech Stack:** Vue 3 + TypeScript, AntV X6 core `2.19.2` + 2.x plugins (pinned, do not upgrade), vitest + jsdom, Playwright `_electron`, lucide-vue-next 1.0.0 icons. **Depends on:** U1, U2 and U3 (`CanvasPropertiesPanel.vue`, `canvas-style.ts`, `panelVisible`, `applyStylePatch`, `CANVAS_DERIVED_CHANGE`, `nodeDraftFromCell`, U2's edge `props` reader).

**Spec:** `docs/specs/2026-10-19-t536-canvas-toolbar.md`. §3 (C1–C6), §7.0, §7.1 row P7, §7.4, §7.6 (Layers column), §8 row U4, §9.3 item 9 ("for Layers, reorder, Save, reopen, assert the order held"), §9.4, §9.5, and "Implementation notes (U3)".

## Global Constraints

- Everything in U1–U3's Global Constraints still holds (no new npm dependency, no X6 upgrade, tokens only, `$t()` with keys in **both** `en.json` and `pt-BR.json`, English everywhere outside i18n files, focus-gated shortcuts, design.md first).
- **No schema change and no new field.** `zIndex` already exists (`canvas-core.ts` `CanvasNode.zIndex`, validated finite, written by `orderedNode`). `src/main/canvas-core.ts` is **not modified** in U4, so every compatibility test runs against the reader the previous release ships.
- **Untouched boards stay byte-identical.** Save adds `zIndex` to a node only when the live order differs from the order the document already renders in. A move, a resize, a rename, a style pick, a duplicate or a new shape is not a restack.
- **Nodes only.** Edges keep `zIndex: 0` in `toX6Edge`, are never passed to `reorderStack`, and never get a `zIndex` in the file (the edge schema has none). Ranks start at `1`, so every node stays above every arrow after any move.
- **Stacking is never derived from X6's own `toFront` / `toBack`.** Those use the graph's min/max z including edges, which would put a node under the arrows (`toBack` → `min - 1 = -1`). The pane computes ranks itself and writes them with `setZIndex`.
- **Agent parity (C6):** `zIndex` on `add_node` / `update_node` in the same PR; `docs/harnu-features.md` updated and its marker bumped (`v97` at U3's head, so `v98` unless main has moved; take the next number at rebase); `docs/user/agent-control.md` updated. The `tool-catalog.ts` description change trips the awareness and user-docs gates, which this PR satisfies rather than labels away.
- **No new top-level component.** The Layers controls live in `CanvasPropertiesPanel.vue`. Update its `CLAUDE.md` file-map row to name `canvas/canvas-layers.ts`.
- **Stop rule (§7.0).** If any part of P7 turns out to need a new library or to risk an existing board (a test in Task 3 or a live-matrix row that cannot be made green), drop P7 from the panel, the verb and the docs in one commit and record it in the PR and the spec's implementation notes. The edge-data fix (Task 4) is a bug fix and ships regardless.

## Review Focus

The five failure modes most likely to bite a user that no existing test covers. Each has a test in its owning task.

1. **The first Save of a board nobody restacked adds `zIndex` everywhere.** A move, a style pick, a duplicate, a new shape, or an agent board that already carries a `zIndex` on two of its nodes must all save without any new `zIndex`. Test in Task 3.
2. **A shape drawn after a restack sinks on reload.** X6 puts a new node at `max + 1` (on top), but with no `zIndex` it would reload at `1`, under every ranked node. Save must notice the live order no longer matches and write ranks. Test in Task 3 (pure) and Task 6 (pane: restack, Save, draw a box, Save, reload, box still on top).
3. **A theme switch after a restack reverts the order, or ⌘Z after the switch restores the wrong one.** The theme redraw rebuilds every cell from the draft; if the draft re-ranks or drops live z, the history's recorded z values no longer describe the board. Test in Task 6.
4. **Send to back puts a node under the arrows, or a move that changes nothing dirties the pane.** Every rank must stay `>= 1` (edges are `0`); a "bring forward" with nothing overlapping above, or "front" on the top node, writes nothing, leaves Undo disabled and the dirty dot off. Test in Task 2 (pure) and Task 6.
5. **Layers is missing where it applies, or writes where it should not.** A mockup card, an unknown kind, and a rubberband that also caught arrows must all show the Layers group (every node takes layers, §7.6), and a move must never give an edge a z other than `0`. The U3 assertions "box + card hides the panel" and "Ctrl+A hides the panel" change on purpose. Test in Task 6.

  ```ts
  export type LayerMove = 'back' | 'backward' | 'forward' | 'front'
  export const LAYER_MOVES: readonly LayerMove[] // ['back','backward','forward','front'] — panel order
  /** The z X6 gives every node without a zIndex on a fresh fromJSON (after clearCells). */
  export const CANVAS_LOAD_Z = 1
  export interface StackBox {
    x: number
    y: number
    width: number
    height: number
  }
  export interface StackNode {
    id: string
    z: number
    bbox: StackBox
  }
  /** Bottom → top as a document renders: stable sort by (zIndex ?? CANVAS_LOAD_Z); ties keep file order. */
  export function documentStackOrder(nodes: readonly { id: string; zIndex?: number }[]): string[]
  /** The z each node is RENDERED with: the file's values when every node has one and they are
   *  distinct, else the ranks of documentStackOrder (1..n). Never written to the file. */
  export function renderStackZ(
    nodes: readonly { id: string; zIndex?: number }[]
  ): Map<string, number>
  /** Bottom → top as the graph holds it: `nodes` in model order, stable sort by z. */
  export function liveStackOrder(nodes: readonly { id: string; z: number }[]): string[]
  /** New bottom → top order, or null when the move changes nothing. `stack` is bottom → top. */
  export function reorderStack(
    stack: readonly StackNode[],
    selected: ReadonlySet<string>,
    move: LayerMove
  ): string[] | null
  /** id → rank, 1-based, bottom → top. */
  export function stackRanks(order: readonly string[]): Map<string, number>
  /** The Save rule: null = keep each node's base zIndex; otherwise the rank every node gets. */
  export function savedZIndexes(
    draftNodes: readonly { id: string; zIndex?: number }[],
    live: readonly string[]
  ): Map<string, number> | null
  ```
  Overlap for `forward`/`backward` is bbox intersection with positive area (touching edges do not overlap). `reorderStack` ignores ids in `selected` that are not in `stack` (an edge id from a rubberband).

## Open points

Decisions this plan makes where the spec is silent or disagrees with itself or the code. Each becomes an "Implementation notes (U4)" entry in the spec if the PR keeps it.

1. **Ranks for every node once restacked, not a minimal write.** The spec only forbids `zIndex` on every node of an _untouched_ board. A minimal write is not expressible: unstacked nodes all load at z 1 and break ties by file order, so "forward" between two of them has no single-node value. After the first real restack every node gets `1..n`; an agent's `zIndex: 100` becomes its rank. Order is kept, values are not.
2. **Forward/backward step past the nearest overlapping node** (tldraw), not one slot in the global list (Excalidraw). The spec names the moves but not their scope; a global step past a far-away node changes nothing visible and reads as a broken button.
3. **Arrows are not layered.** P7 says "selected nodes" and the edge schema has no `zIndex`. Edges stay at 0, nodes at `>= 1`, so arrows always draw under shapes. A file `zIndex <= 0` (possible today, by hand) is lifted above the arrows by the first restack.
4. **The agent's `zIndex` is an integer `>= 1`**, stricter than the reader (any finite number): the verb refuses what the pane would never write, and below 1 would put a node under the arrows.
5. **Visibility widens.** U3 hid the panel for box + mockup card and for `Ctrl+A`; §7.6 gives every shape Layers, so the panel now shows Layers alone there. Two U3 tests change on purpose.
6. **Older builds and new shapes.** A shape drawn in the previous release on a restacked board has no `zIndex`, loads at 1 and reappears near the bottom after reload. Not data loss; documented. The box stays near the bottom until the operator restacks in this build, which then ranks every node.
7. **The edge-data fix (Task 4) is here, not in U5.** U5 is reader-first: the release before it must not lose edge `props`. Today the delete → Save → undo → Save path drops them (and `label`/`router`) in every build, U2's reader included. If U2 has not merged when U4 starts, land Task 4 in U2's branch instead, so "the release containing U2" is safe on its own; U5's merge gate names whichever release first contains it.
8. **No keyboard shortcuts for layers.** The spec puts layers in the panel only; `Ctrl+]`/`Ctrl+[` are left for a follow-up.
9. **The pane renders with distinct z values it never saves** (`renderStackZ`). Not in the spec; found while planning. Today every unstacked node loads at z 1, and X6 breaks ties by its current collection order, so undoing a restack would restore the numbers but not the order. Rendering ranks fixes undo without touching the file, because Save compares orders, not values.
