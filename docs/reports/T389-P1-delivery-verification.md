## 2. How this was checked

**Evidence rule.** An AC is `met` when its named test exists in the PR branch (`git grep` of the title), the test body asserts the AC's observable, and the test is in a passing run I did at the stack tip. `contract` ACs need the golden fixture and replay on both sides; where the spec's own Evidence names only the host side the AC is graded `met` and the open both-sides replay (QA-7) is a `[GAP]`. `mod-test` and `integration` ACs (files under `tests/cli/`, `claude plugin test`) were not run by me (they need a CLI); they are `met` only with a committed run log, `met †` with an uncommitted local pipeline log that postdates the last source commit, otherwise `not-run`. `live-verify` ACs are `met` only with a committed recipe log or smoke addendum (executor-authored, so marked), `not-run` with nothing. `human` ACs are never graded. The PR bodies were used as pointers, never as proof.

**`†` legend.** In every wave except P2W1, `†` means "evidence is an uncommitted local pipeline log in `/tmp/harnu-local-ci-*`, not attached to the PR". In P2W1, `†` means "contract AC graded met on the host-side test the spec names; a mod-side replay of a golden fixture does not exist". `/tmp` is not durable: if those logs are lost the `†` rows revert to `not-run`.
