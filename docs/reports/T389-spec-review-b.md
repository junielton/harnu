## 1. Scope

Edit scope (8 specs, `docs/specs/T389-companion-mod/`): `P3W1-approval-hold.md`,
`P3W2-structured-sentinel.md`, `P4W1-mods-audit-tab.md`, `P4W2-terminal-band-and-commands.md`,

(B) evidence grounding of the whole set against the smoke evidence and the CLI types.

## 2. Method

- Read the smoke evidence, the study, the contract, the master and the ADR in full, then the 8
  specs in full.
- Checked every constant, command, event, ask kind, feature id, `$.state` key and host interface
  the 8 specs use against contract §5 to §11, §22 and master §12. All upper-case constants not
  in contract §7 are declared host-only by their wave (P3W2, P4W4, P4W5) or are env or code
  names.
- Parsed the acceptance criteria of the 8 specs: 216 criteria (217 after AC-P4W2-25), every one with a method from the
  closed list and a named `Evidence:` artifact, no gaps or duplicates in the numbering.
- Checked negative paths (mod absent, lease lost, kill switch, `/clear`, hot reload, headless,
  CLI too old or above the ceiling, managed policy, host down) in each spec's section 8, and the
  docs deliverables (CHANGELOG, `docs/harnu-features.md` plus marker, `docs/user/`, `design.md`,
  i18n) in each section 12.
- Evidence grounding. The path named in the brief for the 2.1.287 types file did not exist when
  I started. The `plugin-authoring` skill writes it when loaded, so I loaded the skill and used
  the file it wrote (20 116 lines, header "Written by Claude Code 2.1.287"). Every "types L<n>"
  citation I sampled landed on the cited declaration. A second copy of the types in the CLI's
  marketplace mods folder is from 2.1.277 and was not used for line checks.
- Ran things instead of only reading (all on the real 2.1.287 binary, scratch plugins under the
  session scratchpad, nothing touching user config):
  1. `claude plugin validate` on a plugin whose `hooks.json` names two modules (RB_1).
  2. `claude plugin validate` on a plugin whose one module imports a `.tsx` view (RB_1).
  3. `claude plugin test` in an empty directory, with and without `disableAllHooks` (RB_5).
  4. `claude -p --settings '{"env":{"CLAUDE_CODE_PLUGIN_DIRS":…}}'` loading a scratch mod (one
     haiku call; supports P4W3 option A in part).
  5. `claude plugin list --json` row and id counts (RB_13).
- Read the source of the `sec-default` mod from the CLI's mods repository copy on this machine
  (its README: "The rows", "Deny rules hold", options). It is the primary source for what the
  organization mod pins (RB_4).
- Spot-checked 14 code references of the 8 specs against the repository (line numbers and
  identifiers): all matched.
- Ran the client-identifier shapes (tracker-key shape, workspace directories, home paths, uuids) over the
  8 specs: no hits.
