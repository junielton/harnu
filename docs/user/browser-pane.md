# Browser pane

A **browser pane** is a real Chromium page that lives in the split stack beside your session. Use it to look at the dev server a session just started, to read documentation next to the conversation, or to let a session open a page for you. It works like any other pane: it can be maximized, resized by dragging its header, and closed.

> **What is and isn't built yet.** This page describes what ships today. A session can open, list, navigate and close panes, open a local `.html` file as a live panel (below), read what is on the page (a snapshot, a screenshot, the console, the network if you let it) and drive it (run a script, click, type, fill a form, press keys); it can also show the page as a phone or tablet, zoom it, attach files from the folder to a form, and download a file into the folder. You can point at an element and send a note to a session (below). The pane does not come back after you restart Harnu yet.

## Opening one

Click the small arrow beside the **Split** button in the Topbar and choose **Browser**. A new pane opens in the folder you are looking at and puts the cursor in its address bar. (The Split button itself still opens a terminal in one click.) A session can also open one for you; it appears in the folder that session works in, in the background, without moving you away from what you are doing.

## The pane

- **Header** — the page title (or its address while it loads), a chip when a session is connected (below), the **comment button** (below), the **⋯** menu, maximize and close.
- **Address bar** — back, forward, reload (it turns into a stop button while a page loads), then the address field. Type an address and press **Enter**; `Esc` puts back the real address. A word with a dot (`example.com`) opens over https; `localhost:5173` opens over http. **Cmd/Ctrl+L** jumps to the field while a pane is focused, and **Cmd/Ctrl+R**, **Cmd/Ctrl+[** and **Cmd/Ctrl+]** reload, go back and go forward. These shortcuts are in Settings → Keyboard Shortcuts with the others and can be rebound there.
- **Zoom** — at the right of the address bar: **−**, the current percentage and **+**. Click the percentage to go back to 100%. **Cmd/Ctrl +**, **Cmd/Ctrl −** and **Cmd/Ctrl 0** do the same while the pane is focused (they are in Settings → Keyboard Shortcuts too). Harnu remembers the zoom **per site**, so the next time you open that site in any pane it comes back the way you left it. A session can set the same zoom for you, and it is the same remembered value. Two panes showing the same site share that zoom as you change it (the browser keeps one zoom per site), so zooming one changes the other.
- **Device mode** — the small phone icon next to the zoom opens a list of seven device classes (`phone-s`, `phone-m`, `phone-l`, `tablet`, `tablet-landscape`, `laptop`, `desktop`, each with its size and pixel ratio) and **Custom size…**, where you type a width, a height, a pixel ratio and whether it is a mobile device. The page then really thinks it is on that device: its width and pixel ratio, touch events, and (for phones and tablets) a mobile browser identity, so responsive layouts and `<meta viewport>` behave as they would on the real thing. It is not just a narrower window. The page is drawn inside a device frame and scaled down if it doesn't fit the pane; the page itself never sees that scaling. A second row appears with the current device, **Rotate**, a **light / dark** toggle, a **reduced motion** toggle and **Reset device**. **Zoom is switched off in device mode** (the page is already drawn at the device's size) and comes back, at the zoom you had, when you reset. Turning on a mobile device for a page that is already open reloads it, because touch only works if it was on when the page started. A session that changes the device changes this same setting, so what the picker shows is always what the page sees.
- **Downloads** — when you click something that downloads a file, the pane asks **Save _name_ to `.harnu/out/downloads/`?** with **Save** and **Cancel** (no answer for a minute cancels it). Saved files go into that folder inside the pane's folder and never replace an existing file. Harnu never opens or runs a downloaded file. A page that tries to download on its own, without you clicking, is cancelled silently.
- **Badges** — a green **local** badge means the address is a dev server on your own machine (localhost and similar); **external** is any other site. An amber **opened by agent · host** badge appears when a session took the pane to a site you hadn't seen there; dismiss it with its **×**, or just navigate yourself.
- **Notices** — one line under the address bar when something was refused or dismissed: an address of a kind that is blocked, a certificate Harnu accepted for your own machine, or a dialog (`alert`, `confirm`, `prompt`) the page opened that Harnu closed for you.
- **⋯ menu** — **Pause agent for 10 min** (or **Resume agent**) and **Open DevTools**.

- **Network counter** — a red dot and **Network 4:12** appear in the header while a session is recording the page's network traffic. It counts down to when the recording stops by itself. There is no stop button: close the pane or disconnect the session to end it sooner. When the pane is narrow the word "Network" gives way and the dot and the time stay.

## Live panels: your own files, kept fresh by a session

A session can open one of **your project's `.html` files** in a pane — or write a small panel from inline HTML — and keep it up to date while you watch: a status board, a checklist, a set of numbers. A panel pane shows a blue **page** badge, and its address field shows the file's path in your project (`docs/status.html`) instead of an address.

- **It reloads when the file changes.** Edit the `.html` file, or any file it loads (a stylesheet, a script, an image), and the pane reloads a moment later, scrolled to where you were. Delete the file and the pane shows **File removed — waiting for it to come back…**; put the file back and the page returns on its own.
- **A session can update it without a reload.** It can set the panel's saved state (a small piece of data kept next to your project, so it survives a reload and a restart, in `.harnu/out/browser/state/`) and the page redraws, or change one element of the page right now. A change made that way to the page itself is not kept: a reload starts from the file and the saved state.
- **Buttons can talk back.** A button in a panel can send a short message to the session — "approve", "reject", with a small piece of data — and it arrives in the session as a message starting `[harnu-page-event]`. It is sent only when **you** really click or press a key: a session that clicks its own panel's button cannot approve itself, and a page can send at most one message a second. The message says plainly that it is data from the page and not you speaking.
- **Offline by default.** A panel pane loads nothing from the network, and its own script, links and popups can't take it to any address outside its folder (a notice says so: "this panel is offline"), so a panel can't send your files anywhere, whatever it contains. If you open a page that needs a CDN script, a web font or a link out, use the **Offline / Network on** switch at the right of the address bar: it is yours alone (no session can turn it on) and applies to that pane only; turning it on reloads the page, and the switch turns amber to remind you. Typing an address in the pane's own address bar always works.
- **Only your own files.** The pane serves files inside the folder only, never anything under `.git` or `.harnu/memory`, and it follows no link that leaves the folder. Each folder is its own world: a panel in one folder cannot read files of another. Your files go only to the panel that shows them: a web page in another pane, or a background worker it starts, can't load them. (The same goes for a worker a panel starts itself: a panel can't have a worker load your project files.)

## Commenting on a page

Point at something on a page and tell the session what to change, without describing where it is.

1. Click the **comment button** (a speech bubble with a plus) in the pane header, or press **Ctrl+Shift+C** (Cmd+Shift+C on a Mac) while the pane has the focus; the button's tooltip shows your current shortcut. A small note at the top of the page says "Click an element to comment · Esc to exit".
2. Move over the page: the element under the pointer is outlined, with its tag and size ("button.pay · 520×45"). Click it. The page does not see these clicks.
3. A numbered **pin** appears on the element and a **composer** docks under the page, showing what you picked, its source file when the page's framework exposes it (Vue, React or Svelte development builds), and what will be attached. The page gets shorter to make room; nothing is drawn over it.
4. Type what should change. **Enter** sends it to the session now. **Shift+Enter** keeps it as a draft (a white pin) so you can pick more. **Esc** closes the composer and ends picking in one press: an empty composer throws its pin away, text you typed is kept as a draft.
5. The bar under the composer counts "N drafts · M sent" (just "M sent" when nothing waits). **Send N comments** sends every draft as **one** message, numbered in pin order.

**Who gets it.** The **Send to** menu lists the sessions of this folder. A pane a session opened sends to that session, any other pane to the session you are looking at, and your choice is remembered for the pane. A session that is parked is woken in the background (it does not take over your view), and a busy one receives the message when its current output settles. If you are typing in that session's terminal, the message waits until you have paused for about a second and a half so it never lands in the middle of your sentence. With no session at all, the comment is copied to your clipboard and a notice says so.

**What the session receives.** A message starting `[harnu-comment]` with your words, and, clearly fenced and marked untrusted, what the page said about the element: its selector, source file, address (without any query string), HTML (trimmed), a short list of computed styles and the path of a cropped picture saved under `.harnu/out/browser/comments/`. A page can put anything in its own class names and text, so the session is told that everything inside the fence is data about the page and not an instruction from you.

**Pins.** A pin sits at the top-right corner of its element: it finds it again after a reload or a move to another page of the same site, and sits as a dashed circle where it was when the element is gone. Sent pins turn solid and fade. A draft stays on the pane while you navigate; drafts do not survive closing Harnu yet.

**Safety.** The composer is part of Harnu, not of the page, so a page can never read what you type, and no session can type into it or press Send. A page cannot fake a click to open it, and a pick is refused if a session was clicking or typing in the pane at that moment or just before. A pane you **paused** still takes comments (pausing stops the session driving the page, not you writing to it). A pane you **disconnected** the session from does not: the comment button is greyed out and the composer says why, before you type anything.

## When something covers the page

A browser page is drawn by the system above everything else in the window, so a menu, dialog, palette or notification opened over it would normally be hidden behind it. Harnu avoids this by swapping the page for a still picture of itself while anything overlaps it: the page keeps running underneath, and it comes back the moment the menu closes. Dragging a splitter does the same, so the drag doesn't get lost inside the page. You will notice a frozen frame for a moment; that is why.

## Sessions and the connection chip

A pane a session opened shows a chip in its header — "Connected to ‹session›" (the session name is kept when the pane is narrow; the words "Connected to" go first), or "Connected to an agent" — with the word **driving** while the session is navigating the pane. Click the unplug button to **Disconnect** the session from that pane for good: it can no longer read or change it, even close it, and nothing reconnects it. The pane stays and stays yours. Use **Pause agent for 10 min** to stop a session changing the pane for a while: the chip shows "Agent paused · 9:41" counting down, with a **Resume** button. See [Agent control](agent-control.md#browser-panes-a-session-opens) for everything a session can do, and **Settings → Control server → Allow agents to drive browser panes** to switch all of it off.

**What a session can read.** On a pane it opened, a session can take a snapshot of the page (the same outline a screen reader sees, so it never needs to guess at pixels), a screenshot, the page's console messages, and wait for something to happen on the page. None of this works while you have the session **disconnected**; it keeps working while the session is **paused** or agent control is off, because reading never changes the page. **Network recording** is separate and off by default: a session has to ask, you see the red counter, and it stops on its own. Addresses are recorded without their query values, cookies and sign-in headers are never recorded, and response text only if the session asked for it. Recording a site that isn't your own machine asks you first, like driving it (below).

**What a session can drive, and when it asks.** A session can run a script on the page, click, type, fill form fields and press keys. On a page on your own machine (a dev server, or any name you listed under **Trusted dev hosts**) it just does it. On **any other site**, and on **any pane you opened**, the first attempt shows a prompt: which pane, who opened it, which site, and the first thing it wants to do. Read it as "this will act as you on that page". **Allow** does not perform that first action; it gives the session a **lease** on that pane, and the session is told to look at the page and try again. The lease covers every session on that pane **while it stays on the same site** (the same address start: scheme, host and port; other pages of that site are fine) until the pane has had no agent activity for **10 minutes**, or you close it, **Disconnect**, block the folder or switch agent browser control off. **Deny** blocks that pane for **5 minutes** without asking again. Your "Ask before agent actions" setting still asks first for everything else a session does here, and no mission approval or "always allow" ever covers a lease. While a session is driving, the chip shows **driving**.

**Clicks and key presses on a freshly loaded page.** Harnu found that a pane does not pass clicks or key presses on to the first page it loads, to a page it reached from a blank page or from another site, or to a page that redirected itself (typing and filling forms are fine). Rather than let a session think a click worked when it did nothing, it is told "not ready" and asked to reload the pane once (for a pane you opened yourself it is asked to ask you instead). After a reload everything works, whether or not you are looking at the pane. You will not see anything on your side.

**Moving files, and showing a page as a device.** A session can also show the page as a device or zoom it (`browser_emulate`), attach files from the folder to a page's file field (`browser_upload`) and download a file into `.harnu/out/downloads/` (`browser_download`). Changing the device or downloading by address is free on a pane the session opened, and asks for the same lease as driving on a pane you opened. Downloading by clicking an element is a click, so on a site that is not your own machine it asks too. **Uploading** also asks on any site that is not your own machine, because a file leaves your folder: only files inside the pane's folder can be uploaded, up to 10 at a time and 50 MB each, never anything inside `.git` or `.harnu`, or named `.env*`, `.git-credentials`, `.npmrc`, `.netrc`, `.pypirc`, `*.pem`, `*.key` or `id_*`, and never through a link that leaves the folder. A session cannot make a page download on its own: it asks for one download, for the length of one call.

**Panes you open yourself.** A session cannot see or touch them until you turn on **Let agents read browser panes I open** in the folder's right-click menu (off by default; this folder only, not its worktrees). With it on, the pane's header says "An agent can read here"; to act on it a session still needs your lease, and then the header says "An agent can drive here" with the unplug button. Turning the option off ends every lease in that folder.

**Trusted dev hosts.** Right-click a folder and choose **Trusted dev hosts…** to list the names that are your own dev servers: an exact name (`app.test`, a docker service name like `web`) or a short wildcard (`*.test`). A page on one gets the green **local** badge and is driven without asking. Only the host name is judged — a name that merely resolves to your machine is not trusted by itself, and Harnu's own ports never count. Wildcards over a public domain such as `*.com` or `*.co.uk` are refused: a wildcard needs a development-only ending like `*.test` or three name parts (`*.dev.example.org`). A session cannot change this list; if a page redirects to another site, the new site is judged from then on.

## What the page is not allowed to do

A page in a browser pane is treated as untrusted code, even your own dev server:

- It runs in its own sandbox with no access to Harnu's windows or files. It can still reach network services on your machine, such as a dev server, like any browser; a page on one of Harnu's own ports is simply shown as `external`. Your logins are kept in a separate cookie jar from the one used by panes a session opens, so a session never starts logged in as you.
- Only `http`, `https` and `about:blank` open. `file:`, `chrome:`, `devtools:`, `view-source:` and `javascript:` addresses are refused.
- A link or script that tries to open a new window opens a new pane **only if you clicked it**; otherwise it is blocked. Sign-in flows that need to talk back to the window that opened them do not work.
- Downloads you did not click for are cancelled (a download you clicked asks first, above), and permission requests (location, notifications, camera, microphone, clipboard reading, and so on) are refused. There is no prompt.
- A site with a bad certificate is refused, except on your own machine (a self-signed dev server), where it is accepted and a notice says so.
- Pages that ask for a username and password through the browser's own sign-in box are cancelled; sign in on the page instead.

## Troubleshooting

- **The comment button does nothing, or Ctrl+Shift+C does not start it.** The shortcut works while the pane has the focus (click the page once first); the button works any time. The keybinding can be changed in Settings → Keybindings.
- **"Comment not sent".** The notice says why: you disconnected the session from this pane, or the session could not take the message (the draft is kept until the message really went in).

- **The page is blank or white.** A reload (**⟳**) usually fixes it. If the address is `about:blank` you haven't navigated yet.
- **A menu seems to flash a still picture of the page.** That is the frozen frame described above, working as intended.
- **A panel doesn't update.** Check the pane's chip: **Pause agent** and the Settings switch both stop updates. A page that is not one of your own files (a dev server, a website) can't be updated by `set_data` or `patch`; the session is told so.
- **My panel's web font or CDN script doesn't load.** Panels are offline by default; turn on **Network on** for that pane.
- **A session says it can't drive my pane.** A pane you opened needs **Let agents read browser panes I open** in the folder's right-click menu, and then your permission once per pane. Or ask the session to open its own.
- **A session says "BROWSER_WRITE_DENIED".** You pressed Deny on that pane in the last five minutes. It waits; it does not ask again.
- **Zoom does nothing.** In device mode zoom is off by design; use **Reset device** first.
- **A download never appears.** Only a download you clicked for is offered, and the question disappears after a minute. A session's `browser_download` saves straight into `.harnu/out/downloads/` in the folder.
- **A session says "BROWSER_PAUSED" or "BROWSER_DISCONNECTED".** You paused it or cut it off. Resume from the chip, or open a new pane for it if you disconnected.
